# OCI Agent Launchpad 템플릿 요구사항

기록일: 2026-11-05

이 문서는 사용자가 요청한 템플릿의 제작 기준을 기록합니다. 실제 현장에서 사용할 수 있도록 상세한 템플릿과 일반적인 활용 예제를 제공하는 것이 목표입니다. 템플릿 자체는 아직 제작하지 않았으며, 현재 작업 범위는 계획과 요구사항 정리입니다.

## 사용자가 요청한 사항

| ID | 요구사항 | 사용자 발언 근거 | 문서와 설계에 반영할 내용 |
| --- | --- | --- | --- |
| REQ-01 | AI-DLC 방법론과 AWS 워크플로를 함께 근거로 사용 | “템플릿을 이걸 근거로 만들어야 하지 않아? 이거랑 aws ai-dlc workflow 링크랑” | 두 자료를 대조하여 템플릿의 절차와 산출물을 설계합니다. 자체적인 워크숍 양식만 만드는 것으로 대체하지 않습니다. |
| REQ-02 | 실제로 사용할 수 있을 만큼 상세한 템플릿 제공 | “이게 자세한 템플릿으로 되어있어야 써먹을 수 있을거 같은데?” | 개요뿐 아니라 입력 항목, 작성 방법과 진행 방법을 구체화합니다. |
| REQ-03 | 필수와 옵션을 구분 | “그래 필수/옵션값 형태면 괜찮지 않나?” | 모든 항목을 일괄 강제하지 않고 필수 항목과 선택 가능한 항목을 표시합니다. |
| REQ-04 | 일반적인 예제 여러 개로 사용 방법 설명 | “일반적 예 몇개를 가지고 이렇게 하는거라고 보여줄 수 있으면 좋겠어” | 예제를 통해 템플릿이 어떻게 채워지고 진행되는지 보여줍니다. 구체적인 예제 종류와 개수는 아직 확정하지 않았습니다. |
| REQ-05 | OCI에서 AgentCore 역할을 대체할 구성도 계획 | “oci에는 agentcore가 없잖아 그거에 대한 대체 구성도 해보자고. 일단 계획.” | 실행·세션·메모리·도구 권한·관측·평가 등의 대체 구성을 배포·운영 설계에 연결합니다. |
| REQ-06 | 우선 계획하고 내용을 문서로 기록 | “일단 계획”, “내가 말한거 문서로 기록해주고.” | 요구사항과 설계를 먼저 기록합니다. 이 기록을 구현·배포 완료로 취급하지 않습니다. |
| REQ-07 | 기존 프로젝트를 연결하여 개발·배포·모니터링 | python-foundation과 OCI AgentCore 대체 구성을 활용해 앱을 만들고 OCI Companion에서 배포·모니터링하자는 사용자 요청 | [연계 계획](companion-integration-plan.md)을 템플릿과 예제의 목표 흐름에 반영합니다. |
| REQ-08 | AgentCore 주요 기능 제공 | “agentcore에 있는기능이 되어야 해 큰기능들은” | 플랫폼 주요 기능을 제공 목표로 두고 앱별 옵션과 분리합니다. [주요 기능 기준](oci-agent-platform-plan.md#주요-기능-제공-요구와-완료-기준)에 세부안을 기록합니다. |

이 표의 발언은 이 프로젝트 대화에서 발췌한 짧은 요구사항 근거입니다. 회의 녹취 전체나 민감한 고객·인사 내용은 포함하지 않습니다.

## 템플릿의 근거 자료

- [AI-DLC Method Definition 원문](https://prod.d13rzhkk8cj2z0.amplifyapp.com/aidlc.pdf): 방법론의 원칙과 사람·AI의 역할을 확인할 기준입니다.
- [AWS AI-DLC Workflows](https://github.com/awslabs/aidlc-workflows): 실제 에이전트 진행 지침과 산출물 구조를 확인할 기준입니다.
- 사용자 제공 회의 녹취: 고객 준비와 현장 공동 개발, 후속 운영 전환의 맥락입니다.
- [OCI AgentCore 대체 구성 계획](oci-agent-platform-plan.md): OCI 배포·운영 설계의 초기 검토안입니다.

앞선 기획 문서에서 두 공개 자료를 참고했지만, 템플릿별 원문 대응표와 사용할 워크플로 버전은 아직 확정하지 않았습니다. 제작 전 원문의 어느 부분을 유지하고 무엇을 OCI용으로 추가·변경하는지 확인해야 합니다.

## 상세화 제안

다음 내용은 사용자 요구를 충족하기 위해 대화 중 제안한 설계 방향입니다. 사용자 확정 요구와 구분하며, 세부 형식은 이후 설계에서 결정합니다.

### 템플릿 한 항목에 담을 정보

| 항목 | 설명 |
| --- | --- |
| 이름과 목적 | 무엇을 결정하거나 기록하는지 설명 |
| 필수 또는 옵션 | 반드시 작성할지 선택할 수 있는지 표시 |
| 적용 조건 | 옵션 선택이나 업무 특성에 따라 필요한 후속 항목 표시 |
| 입력 형태 | 자유 서술, 선택값, 표 등 값의 형태와 허용 범위 |
| 작성 안내와 예시 | 처음 사용하는 사람이 참고할 수 있는 구체적인 설명 |
| AI의 확인 질문 | 값이 없거나 모호할 때 확인할 질문 |
| 확정 시점과 확인 역할 | 어느 단계까지 누가 확인해야 하는지 표시 |
| 완료 조건 | 다음 단계로 진행할 수 있는 판단 기준 |
| 근거와 연결 | 원문 근거 및 관련 요구사항·설계·평가 항목 연결 |

필수·옵션 구분을 기본으로 하고, 특정 옵션을 선택하면 관련 항목이 필수가 되는 조건을 붙이는 방식을 제안합니다. 예를 들어 장기 메모리는 옵션이지만 사용한다면 저장 목적, 접근 범위와 보존·삭제 방법을 정해야 합니다.

미정과 미사용은 구분합니다. 권장값은 제안으로 표시하고, 고객이 확인하지 않은 값을 확정된 요구사항으로 바꾸지 않습니다. 필수 항목도 처음부터 모두 고객이 작성하기보다 AI가 초안을 만들고 부족한 정보를 질문하는 방식으로 구체화합니다.

### 함께 제공할 자료

- 고객·진행자가 작성하는 입력 양식.
- AI가 입력을 읽고 질문·산출물 생성·검증을 진행하는 단계별 지침.
- 작성된 산출물 예시와 단계별 통과 조건.
- 중단 후 이어가기 위한 현재 단계, 미결정 사항과 다음 작업 기록 방식.
- AI-DLC 공통 부분, OCI 적용 부분, 고객별 작성 결과의 구분.

YAML 형식은 설명을 위한 예시로 제시했을 뿐입니다. 실제 파일 형식, 디렉터리와 실행 도구는 아직 결정하지 않았습니다.

## 예제 구성 제안

아래 네 가지는 대화 중 제안한 후보이며, 사용자가 특정 사례나 개수를 확정한 것은 아닙니다.

| 후보 | 고객 요구 예시 | 설명할 차이 |
| --- | --- | --- |
| 사내 문서 안내 | 직원의 규정 질문에 근거를 붙여 답변 | 검색, 출처, 문서 접근 권한, 답을 모를 때의 처리 |
| 매출·재고 조회 | 자연어로 실적과 재고 확인 | 업무 용어, 계산 기준, 조회 권한과 결과 검증 |
| 업무 요청 접수 | 문의를 확인하고 서비스 요청 등록 | 도구 호출, 사용자 확인, 변경 권한, 중복 방지와 실패 처리 |
| 기존 서비스 확장 | 기존 고객 포털에 상담 기능 추가 | 기존 코드·인증·API 분석, 변경 범위와 회귀 검증 |

각 예제는 다음의 연결을 보여주는 구성을 제안합니다.

고객의 짧은 요구 → AI 확인 질문 → 고객의 예시 답변 → 필수·옵션 선택 → 작성된 요구사항 → 설계 선택과 이유 → 작업 분해 → 검증 → OCI 배포·운영 인계.

최종 양식뿐 아니라 어떤 답변 때문에 설계와 필수 항목이 달라졌는지도 설명합니다. 예를 들어 조회만 하는 사례와 실제 요청을 등록하는 사례의 권한·중복 방지 요구를 비교할 수 있습니다.

사내 문서 안내를 전체 과정을 설명하는 기본 예제로 만들고 다른 사례에서는 차이를 강조하는 방식이 후보입니다. 예제에는 합성 데이터와 가상 고객을 사용하며, 설명용 예상 결과와 실제 실행·검증 결과를 구분하는 방식을 제안합니다.

## 기존 계획과의 관계

[고객 공동 개발 프로그램 계획](oci-ai-dlc-plan.md)은 고객 발굴과 워크숍·후속 운영의 초기 기획안입니다. [AgentCore 대체 구성 계획](oci-agent-platform-plan.md)은 기술 기반의 초기 설계안입니다. 두 문서만으로 상세 템플릿 요구가 충족된 것은 아닙니다.

앞으로의 구체화는 AI-DLC 두 원문의 대조와 템플릿 설계를 중심에 둡니다. 3일 워크숍 일정이나 특정 OCI 구성을 원문 방법론의 고정 규칙처럼 적용하지 않습니다. 기존 계획의 파일럿 수, 기간, 첫 업무와 기술 선택은 검토안으로 유지합니다.

## 다음 설계에서 정할 사항

1. 기준으로 삼을 AWS 워크플로 버전과 원문 대응표.
2. 단계별 템플릿 목록, 필수·옵션과 적용 조건.
3. 사용자 입력과 AI 생성·확인 작업의 구분.
4. 예제 종류·개수와 전체 과정을 보여줄 기본 예제.
5. OCI 공통 구성과 고객별 선택 영역.
6. 다른 진행자가 템플릿과 예제만으로 따라 할 수 있는지 확인하는 검증 방법.

이 기록은 사용자가 요청한 제작 기준을 정리한 문서이며, 상세 템플릿이나 예제의 제작·실행 완료를 의미하지 않습니다.
