## 적용 순서

1. **다음 우선순위:** OPS-001/002의 읽기 전용 사전 점검·오류 안내. 조회 범위가 불완전하면 정책 총량을 확정하지 않습니다. 계정마다 한도가 같다고 하드코딩하지 않습니다.
2. **다음 자동화:** OPS-004 bootstrap 점검과 OPS-003 실패 단계 표시. 정책 변경·권한 수정은 대상과 diff가 명확한 실행 계획으로 제공합니다.
3. **배포 연결:** 검증된 release.json → Registry → 관리자 허용 manifest → 배포 요청을 연결해 수작업을 줄입니다. 빌드 성공과 배포 성공은 별도로 기록합니다.

각 항목은 재현 입력, 안전한 진단, 해결 제안, 구현 커밋, 자동 검사, 실제 환경 결과를 연결한 뒤 완료로 바꿉니다. 계정 키·DB 비밀번호·원문 로그 전체·불필요한 개인 정보는 기록하지 않습니다.
