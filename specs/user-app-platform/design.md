# 사용자 앱을 등록하고 운영하는 공통 실행 계층

목적은 사용자가 작성한 Python·Java 등의 앱을 변경하지 않고 최소 실행 규약으로 등록·빌드·실행·상태 확인·로그 조회·버전 복구하는 것입니다. 모델 SDK, MCP, Foundation, SDD와 상세 계측은 선택 사항입니다. 앱은 프로세스로 독립 실행하고 관리 도구를 매 요청마다 호출하지 않습니다.

## 이번 구현

사용자가 지정한 로컬 프로젝트의 app.json에서 앱 ID, 버전, 복사할 파일, argv 형식의 빌드/실행 명령, HTTP readiness 경로를 읽습니다. 언어별 분기 없이 명령을 실행합니다. 소스는 별도 릴리스 폴더에 복사하고 빌드 후 파일 SHA-256을 보관합니다. 배포 시 해시를 재검사합니다. 신규 프로세스를 새 loopback 포트에서 시작하고 HTTP 200을 확인한 후에만 현재 버전을 바꿉니다. 실패하면 신규 프로세스를 종료하고 기존 정상 프로세스를 유지합니다. 이전 정상 버전은 명시적 rollback으로 재실행할 수 있습니다.

관리 서버는 loopback에 바인딩하고 모든 관리 API는 별도 파일의 Bearer 토큰을 요구합니다. CLI는 같은 API를 사용합니다. 프로세스 핸들은 서버가 직접 소유하며 저장된 PID를 믿고 외부 프로세스를 종료하지 않습니다. 서버 종료 시 자식 프로세스를 정리합니다. 등록된 파일과 로그는 남지만 실행 상태 자동 복원은 이번 범위가 아닙니다.

공통 계약으로 OCI OKE Deployment와 내부 Service도 생성합니다. 이미지는 digest로 고정하고 서비스 계정 토큰 자동 마운트를 끕니다. 렌더러는 모델·메모리·Foundation·특정 앱의 환경 변수를 강제하지 않습니다. OCI 생성·배포·이미지 빌드는 별도 기존 도구 경로이며 실제 클라우드 검증과 로컬 실행을 구분합니다.

## 경계

로컬 실행기는 승인한 사용자 코드만 받는 단일 운영자 개발용 도구입니다. 임의 고객 코드에 대한 격리 샌드박스나 멀티테넌트 호스팅이 아닙니다. 파일 경로 이탈·심볼릭 링크·중복 버전·암호 파일의 우발적 복사를 거부하고 shell=False로 실행하지만, 빌드/실행 명령 자체는 현재 OS 사용자의 권한을 갖습니다. 새 의존성 설치나 전체 환경 변수 상속은 자동으로 하지 않습니다. 외부 저장소 다운로드·비밀 관리·인증·공개 진입점은 후속 통합 대상입니다.

HTTP 200은 readiness만 확인하며 업무 정답이나 모델 품질을 보증하지 않습니다. 모델·도구·토큰·비용 추적은 앱의 별도 계측이 필요합니다. 상태·표준 출력/오류·버전 관리와 상세 AI 관측을 혼동하지 않습니다. 포트 교체는 운영 트래픽 전환이나 무중단 배포를 뜻하지 않습니다.

## 완료 기준

같은 관리 API로 Python 소스와 Java JAR 빌드를 각각 등록하고 v1 실행, v2 전환, 실패 버전 거부, v1 복구, 상태/로그 조회를 실제로 확인합니다. Java는 JDK 21 도구가 필요합니다. 프레임워크·모델·클라우드 없이 수행하여 플랫폼 계약이 특정 예제에 종속되지 않음을 확인합니다. 고의 실패 시 기존 앱의 PID/포트/응답이 유지되는지 검사합니다. 등록 후 파일 변조와 잘못된 경로·중복 버전도 거부합니다.
