# 개발자에게 넘길 변경 작업 지시서

기존 프로젝트의 명세와 코드 위치를 근거로 변경 작업을 다른 개발자나 도구에 전달하고, 반환된 구현을 기존 검증 도구로 확인할 수 있도록 한다.

- prepare는 프로젝트 root, 명세 폴더, 요구 ID, 변경 요청, 합격 조건을 받는다. 제공 방식·AI 도구는 지정하지 않는다.
- 링크가 유효한 기존 명세에서 요구 본문, 구현·테스트 위치, 검증할 테스트 이름을 모은다. 변경 요청과 합격 조건은 사용자가 작성하며 자동 승인하지 않는다.
- 새 폴더에 TASK.md와 baseline.json을 만든다. 원본 소스는 복사·수정하지 않고 저장소 상대 경로와 SHA-256을 기록한다. 수신자는 해당 프로젝트 checkout을 별도로 확보해야 한다.
- check는 연결된 전체 명세 파일의 변경을 비교한다. 변경은 재검토 신호이며 구현 성공·실패 판정이 아니다. 테스트를 실행하지 않는다.
- 다른 프로젝트는 --root로 읽는다. 경로는 해당 root 내부여야 하고 출력 폴더는 기존 파일을 덮어쓰지 않는다.
- 실제 테스트 실행기에도 --root를 추가해 반환된 구현을 명시적으로 실행할 수 있게 한다. 기본값은 기존 저장소이며 기존 명령과 호환한다.
- 자격 증명·외부 모델·네트워크·자동 코드 적용·배포는 범위 밖이다. 해시 범위는 연결 파일에 한정되며 모든 의존 파일이나 의미적 합격을 보증하지 않는다.

완료 기준: 별도 임시 프로젝트에서 작업 전달 → 코드 변경 감지 → 실패 테스트 확인 → 구현 수정 → 실제 테스트 통과를 재현한다. 경로 이탈·덮어쓰기·없는 요구를 거부하고 기존 예제도 회귀 검증한다.
