# 요구에서 테스트까지 한 번에 체험하기

이 예제는 **요구를 검토하고 구현 명세와 연결한 뒤, 테스트 결과를 남기고 변경 시 다시 확인할 부분을 찾는 과정**을 보여드립니다. 개발자가 SDD 흐름을 처음 확인할 때 사용하시면 됩니다. OCI 계정·AI 모델·추가 패키지는 필요하지 않습니다.

## 처음 실행하기

Git과 Python 3.12 이상이 있는 환경에서 실행합니다.

```sh
git clone https://github.com/devmrko/oci-agent-launchpad.git
cd oci-agent-launchpad
mkdir -p .run
python3 scripts/sdd_demo.py --output .run/sdd-demo
```

이미 저장소를 내려받으셨다면 저장소 루트에서 마지막 두 명령만 실행하세요. 재실행할 때는 `--output .run/sdd-demo-2`처럼 새 이름을 지정합니다. 기존 결과를 덮어쓰지 않습니다.

정상 완료 시 `DEMO_PASS`와 테스트 수, 예상 결과 확인 목록이 출력됩니다. **DEMO_PASS는 아래 데모 시나리오가 예상대로 동작했다는 의미이며, 고객 검토 완료나 배포 승인이 아닙니다.**

## 무엇을 확인하나요

| 순서 | 예제에서 하는 일 | 기대 결과 |
|---|---|---|
| 1 | 합성 인터뷰의 답변을 요구 초안으로 옮깁니다 | 요구 2개, 미정 질문 1개가 남음 |
| 2 | 계산 요구 REQ-001에 데모 검토 기록을 남기고 기존 구현 명세에 연결합니다 | REQ-001만 검토 기록이 있고 REQ-002는 초안 상태 |
| 3 | 구현 명세의 요구 6개에 연결된 테스트 15개를 실행합니다 | 테스트 통과와 실행 당시 파일 해시를 JSON으로 저장 |
| 4 | 인터뷰에서 숙박 상한을 21박에서 21박으로 바꿉니다 | 요구 재검토 필요. 기존 코드 테스트의 통과 기록만으로 새 요구를 충족한다고 볼 수 없음 |
| 5 | 복사한 구현 파일에 주석을 추가합니다 | 파일 해시가 달라져 테스트 근거가 오래된 상태(STALE)로 바뀜 |

4번과 5번은 각각 최초 상태와 비교합니다. 주석 추가도 변경으로 감지하며, 변경의 의미나 영향 크기를 자동 판단하지 않습니다. 실제 21박 기능을 구현하는 예제는 아닙니다.

## 결과물 살펴보기

`.run/sdd-demo/summary.json`에는 위 단계별 관찰 결과와 예상 상태의 일치 여부가 들어갑니다. `.run/sdd-demo/workspace/`에는 원본에서 복사한 명세·코드·테스트 및 다음 결과가 남습니다.

- `handoff/`: 합성 인터뷰 원문, 요구 초안, 데모 검토 기록
- `binding.json`: 인터뷰 요구와 구현 명세를 연결한 근거
- `test-evidence.json`: 실제 테스트 결과와 파일 해시
- `source-updated.json`: 상한을 21박으로 바꾼 합성 인터뷰

원본 앱 파일은 수정하지 않습니다. 데모 종료 후 작업 폴더의 구현 파일에는 의도적으로 주석이 추가되어 있으므로, 저장한 테스트 근거는 오래된 상태입니다. `.run` 결과는 Git에서 제외됩니다.

오류 종료 코드 `1`이면 기존 출력 폴더 사용 여부, 상위 폴더 존재 여부와 원본 파일을 확인하세요. `2`이면 `summary.json`에서 값이 `false`인 예상 결과와 단계별 상태를 확인하세요. 테스트를 실행할 수 있는 로컬 환경이 필요하며, 테스트 코드를 격리하는 보안 샌드박스는 아닙니다.

## 자신의 프로젝트에 적용하려면

이 명령은 고정된 합성 자료를 쓰는 체험용입니다. 실제 요구를 자동 승인하지 않습니다. 자신의 프로젝트에서는 아래 도구를 각각 사용해 사람이 요구와 연결 관계를 검토합니다.

1. [인터뷰 답변에서 요구 초안 만들기](../interview-handoff/README.md)
2. [검토한 요구를 구현 명세에 연결하고 변경 확인하기](../change-impact/README.md)
3. [연결된 테스트를 실행하고 결과 보관하기](../test-evidence/README.md)

Markdown 명세와 JSON 연결 파일을 직접 작성해 시작할 수도 있습니다. 특정 챗봇·IDE·AI 도구는 필수가 아닙니다. 앱 자동 생성, 실제 OCI 배포와 운영 인수까지 자동 완료하는 기능은 아직 포함하지 않습니다.

체험의 시작 자료는 [14박 변경을 반영한 합성 인터뷰 revision 2](../interview-handoff/interview.14-nights.example.json)입니다. 이전 10박 답변도 수정 이력으로 보존합니다. 실제 10→14박 구현은 [변경 사례](../travel-allowance/change-14-nights.md)에 있습니다.
