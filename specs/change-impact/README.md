# 요구 변경이 어떤 코드와 테스트에 연결되는지 확인하기

인터뷰에서 검토한 요구를 구현 명세의 요구에 명시적으로 연결하고, 이후 변경된 요구·파일·시험 위치를 확인합니다. 담당자가 수정 범위와 재검증 대상을 찾는 데 사용하는 도구이며 코드를 자동 수정하거나 테스트·배포를 실행하지 않습니다.

연결은 일반 JSON 기준 파일로 저장합니다. 특정 챗봇·IDE·클라우드 계정이 필요하지 않습니다. 두 요구의 의미가 맞는지는 연결하는 사람이 검토하며 번호가 같다는 이유로 자동 연결하지 않습니다.

## 합성 사례로 연결하기

먼저 [인터뷰 근거 연결 안내](../interview-handoff/README.md)에 따라 `.run/my-sdd-draft`를 생성하고 합성 REQ-001의 검토 기록을 남깁니다. 실제 고객 승인이나 배포 승인이 아닌 기능 시험입니다.

```sh
python3 scripts/spec_impact.py bind \
  --handoff .run/my-sdd-draft \
  --source-requirement REQ-001 \
  --target specs/travel-allowance \
  --target-requirement REQ-001 \
  --source specs/interview-handoff/interview.example.json \
  --reason '합성 숙박비 요구와 규정 계산 구현 명세를 연결' \
  --output .run/travel-binding-v1.json
```

출발 요구는 검토 기록이 있고 제공한 최신 인터뷰와 일치해야 합니다. 도착 명세의 요구·코드·테스트 링크도 존재해야 합니다. 연결 이유는 사람의 판단 기록이며 도구가 의미적 일치를 보증하지 않습니다. 기존 출력 파일은 덮어쓰지 않습니다.

기준 파일에는 source 내용 fingerprint, 대상 요구 절·연결 목록, 코드·테스트·설계·작업 파일 해시가 저장됩니다. 원문 전체를 추가 복사하지 않지만 프로젝트 식별자·경로·연결 이유가 있으므로 실제 고객 자료는 공개 전에 검토해야 합니다.

## 변경 확인

```sh
python3 scripts/spec_impact.py check .run/travel-binding-v1.json \
  --source specs/interview-handoff/interview.example.json
```

| 결과 | 의미와 다음 행동 |
|---|---|
| `UNCHANGED` · 종료 코드 0 | 제공한 source와 연결된 파일이 기준과 같습니다. 테스트 합격이나 운영 승인을 뜻하지 않습니다 |
| `REVIEW_REQUIRED` · 종료 코드 2 | 검토·수정·재검증할 대상이 있습니다. `reasons`, `changed_files`, `potentially_affected_requirements`, `tests_to_review`를 확인합니다 |
| 오류 · 종료 코드 1 | 입력 손상·프로젝트 불일치·잘못된 경로 등으로 판정할 수 없습니다. 이를 변경 없음으로 취급하지 않습니다 |

보고서는 `tests_executed=false`를 명시합니다. `tests_to_review`는 다시 살펴볼 시험 목록이며 실제 실행 결과가 아닙니다. 같은 구현 파일을 사용하는 요구도 잠재 영향 목록에 포함합니다. 파일 단위 비교이므로 주석 변경도 재검토를 유발할 수 있습니다.

예를 들어 인터뷰에서 숙박 상한을 10박에서 14박으로 바꿨다면 최신 export를 `--source`에 지정합니다. 기존 검토는 재검토로 표시되고 연결된 규정 계산 요구와 시험 목록이 표시됩니다. 명세·코드·화면·경계 시험을 함께 수정하고 실제 테스트를 실행한 뒤, 수정된 source와 검토 기록을 바탕으로 새 `v2` 기준 파일을 만듭니다. 이전 기준은 보존합니다.

## 어디까지 확인하나요

명세 묶음과 인터뷰 초안은 저장소 상대 경로를 사용합니다. 최신 인터뷰 파일은 매번 명시적으로 제공합니다. 외부 인터뷰 시스템을 자동 조회하지 않으며, 새 파일을 제공하지 않으면 그 이후 답변 변경은 알 수 없습니다.

해시는 내용 변화 감지용이며 인증된 전자서명은 아닙니다. 기존 검토 기록과 연결 파일 모두 로컬 운영자가 관리하는 자료입니다. 이 기능은 요구의 완전성, 테스트의 충분성, 변경의 실제 업무 영향, 배포 가능 여부를 자동 판정하지 않습니다.
