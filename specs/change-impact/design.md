# 검토한 요구와 구현 명세의 변경 영향 연결

2026년 11월 9일 구현 전 설계. 인터뷰 초안의 검토 기록과 기존 구현 명세를 사람이 명시적으로 연결하고, 기준 시점 이후 바뀐 파일·요구·시험 목록을 조회합니다. Python 표준 라이브러리와 기존 두 검사 모듈을 재사용합니다.

## 완료 조건

- 연결 생성은 최신 source 파일을 명시해야 하며, source 프로젝트가 같고 해당 요구가 REVIEW_RECORDED 상태여야 합니다. 초안·재검토 요구는 거부합니다.
- 출발 요구와 도착 요구 ID를 따로 받습니다. 번호가 같다는 이유로 자동 연결하지 않습니다. 연결 이유를 기록하지만 도구가 두 요구의 의미적 동등성을 판정하지 않습니다.
- JSON 기준 파일에 source fingerprint, 도착 요구 절의 해시, 연결 목록, 구현·테스트 파일 해시를 보존합니다. 출력은 신규 파일만 허용합니다.
- 검사 시 최신 source, 요구 문장, 도착 명세, 연결 목록, 구현·테스트의 변경·삭제를 구분하고 재검토 대상으로 표시합니다. 변함없으면 UNCHANGED이며 업무 합격을 뜻하지 않습니다.
- 파일 변경 시 연결된 테스트 목록을 보여주되 자동 실행하거나 PASS라고 표시하지 않습니다. 다른 요구가 같은 파일을 사용하면 해당 요구도 잠재 영향 대상으로 보여줍니다.
- 저장소 밖 경로·symlink 탈출·다른 프로젝트를 거부합니다. 오류·자료 손상은 unchanged로 처리하지 않습니다. 명세·코드·검토 기록을 자동 수정하지 않습니다.

## 범위와 한계

현재는 사람이 제공한 최신 export와 파일 해시 기반 비교입니다. 외부 인터뷰 시스템을 실시간 조회하지 않으며 변경의 의미·영향 범위를 정밀 분석하지 않습니다. source snapshot의 부수 정보만 달라도 보수적으로 재검토합니다. JSON은 위변조 방지 서명이나 고객 승인이 아닙니다. 기존 자료는 덮어쓰지 않고 재검토 후 새 기준 파일을 만듭니다.

입력 명세는 기존 `spec.md`와 `traceability.json`입니다. source·target 묶음은 저장소 상대 경로로 관리하며 실제 원문 포함 초안·기준 파일은 `.run` 등 Git 제외 위치에 둡니다. 저장소를 다른 도구에서 열어도 같은 경로로 검사할 수 있습니다.

## 시험

변경 없는 연결, 미검토 요구 거부, 요구 문장 변경, source 수정, 구현 파일 변경·삭제, 연결 테스트 삭제, 대상 명세 변경, 다른 프로젝트, 외부 경로, 기존 기준 파일 보호를 검증합니다. 합성 CLI로 생성→검사→파일 변경→재검토 보고를 재현합니다.
