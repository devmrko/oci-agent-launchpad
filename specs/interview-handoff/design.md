# 인터뷰 답변에서 검토 가능한 요구 초안으로

고객 인터뷰나 직접 작성한 답변을 일반 JSON 파일로 받아 요구 초안을 만듭니다. 사람이 문장을 다듬고 원문을 대조한 뒤 검토 기록을 남길 수 있게 합니다. UI·LLM·Foundation·OCI를 필수 의존성으로 두지 않습니다.

2026년 11월 9일 구현 전 설계. 이번 범위는 로컬 CLI와 합성 예제이며 기존 미커밋 인터뷰 앱은 수정하지 않습니다. 실제 고객 요구 확정·전자서명·자동 코딩·배포는 범위 밖입니다.

## 계약과 성공 조건

1. 인터뷰 JSON은 `schemaVersion=1`, 프로젝트 `id`, 양의 `revision`, `questions`, `answers`를 갖습니다. 기존 인터뷰 export의 필드 구조를 읽을 수 있으며 별도 화면 없이 직접 작성할 수도 있습니다.
2. 질문·답변 ID 중복, 없는 질문 참조, 분기하거나 순서가 잘못된 답변 정정 연결을 거부합니다. 같은 질문의 마지막 답변만 사용하며 `deferred`는 요구로 승격하지 않습니다.
3. 새 폴더에 원본 snapshot과 `requirements.json`을 저장합니다. 요구는 답변 원문을 그대로 옮긴 **초안**입니다. 명세로서의 적절성·완전성을 자동 판정하지 않습니다. 미정 항목도 따로 보존합니다.
4. 검토 기록은 요구 ID·내용·근거 답변·source snapshot의 SHA-256과 검토자 기재값을 함께 저장합니다. 새 UUID 파일로 추가하며 이전 기록을 덮어쓰지 않습니다. 이름은 자기 기재이고 고객 신원이나 실제 합의를 인증하지 않습니다.
5. 요구 문장이나 원본이 변경되면 기존 기록은 재검토 상태가 됩니다. `status --source 최신파일`로 프로젝트와 현재 revision을 대조합니다. 최신 파일을 제공하지 않으면 snapshot만 확인했다는 범위를 표시합니다.
6. 검토 없는 초안은 DRAFT입니다. 해시가 맞는 기록은 REVIEW_RECORDED이고, 달라지면 REVIEW_REQUIRED입니다. 코드 검사·업무 합격·배포 승인과 구분합니다.

## 파일과 경계

입력 JSON 4MiB 이하, 질문 100개·답변 500개 이하, 요구 100개 이하로 제한합니다. source는 복사해 보존하며 외부 서비스로 전송하지 않습니다. 생성 폴더 0700·파일 0600, 기존 출력 폴더에는 덮어쓰지 않습니다. 입력에 있는 경로나 명령은 실행하지 않습니다. 실제 원문이 포함되므로 출력은 기본적으로 Git 제외 폴더에 둡니다. 자동 비밀 탐지·마스킹은 이 기능의 범위 밖입니다.

## 검증

정상 초안→검토 기록→현재 snapshot 판정, 요구 수정 후 재검토, 최신 source 수정 후 재검토, 다른 프로젝트 거부, 미정 보존, 중복·잘못된 정정 연결 거부, 기존 출력 무변경을 자동 시험합니다. 합성 CLI 실행을 별도로 재현합니다.
