# 구현과 확인 순서

1. 현재 성공한 명령 근거에서 업무 명세와 실행 파일 해시를 모아 식별 정보를 생성한다.
2. 앱 시작 경계에서 설치 파일을 비교하고 불일치 시 실패시킨다.
3. health·채팅·실제 OTLP payload의 동일 식별자 전달과 요청 덮어쓰기 거부를 검사한다.
4. OKE 환경 변수·Pod annotation 연결을 검사한다.
5. wheel을 별도 설치하고 생성된 식별 정보로 실제 설치 모듈을 검사한다.

로컬 완료 기준은 위 파일·API·관측 payload 배선이다. 새 OCI 배포와 실제 Langfuse 조회는 별도 완료 기준으로 남긴다. 과거 기록의 해시를 추정해 채우지 않는다.
