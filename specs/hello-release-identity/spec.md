# Hello Agent의 새 실행에 릴리스 근거 남기기

새 Hello Agent 릴리스를 준비할 때 명세·실행 소스·검증 기록의 해시를 하나의 식별 정보로 묶습니다. 실행 응답과 Langfuse 관측에 같은 식별자가 남아 어떤 파일을 검증한 앱인지 추적할 수 있습니다. 과거 배포의 빈 정보를 추정해서 채우지 않습니다.

## REQ-001 검증한 파일로 식별 정보 생성

명시적으로 실행한 릴리스 테스트 명령이 성공했고 대상 파일이 그대로일 때만 JSON을 생성합니다. 필수 실행 파일·명세·테스트가 검증 범위에 포함되어야 합니다. 출력 덮어쓰기와 오래된 근거는 거부합니다. 명령 성공은 요구사항 충족의 자동 승인이 아닙니다.

## REQ-002 실행 파일과 일치 확인

식별 정보를 설정하면 앱 시작 시 문서의 해시와 설치된 실행 파일 해시를 확인합니다. 불일치하면 시작을 거부합니다. 설정하지 않은 기존 실행 방식은 유지하고 릴리스 근거가 없음을 명시합니다.

## REQ-003 응답과 관측에 같은 식별자 전달

health·인증된 채팅 응답·모델/도구/루트 관측에 동일 release_id와 명세·소스·검증 해시를 전달합니다. 설정된 식별 정보를 요청 입력으로 바꿀 수 없습니다. 실제 모델과 외부 관측 서비스는 로컬 검증에서 대역으로 교체하며 실제 OCI 검증이라고 표시하지 않습니다.

## REQ-004 배포 명세에 선택적으로 연결

OKE 렌더러는 명시적으로 제공한 식별 정보를 환경 변수로 전달하고 Pod annotation에 release_id를 표시합니다. 기존의 digest 고정 이미지와 리소스 구성을 유지합니다. 배포 명세를 생성한 것만으로 이미지 내용 또는 실제 배포의 연결을 증명하지 않습니다.
