# 기존 테스트 명령의 실행 근거

기존 unittest 요구별 판정은 유지하고, 언어와 무관한 명령 실행 근거를 별도 형식으로 추가합니다.
입력 JSON은 명세 경로·관련 요구 ID·해시를 남길 파일 목록이며 명령은 포함하지 않습니다.
사용자가 CLI의 -- 뒤에 지정한 argv만 shell=False로 프로젝트 루트에서 실행합니다.
명세와 계획 파일 자체도 해시에 포함하며 프로젝트 밖 경로·심볼릭 링크는 거부합니다.

결과는 COMMAND_SUCCEEDED/COMMAND_FAILED/TIMED_OUT/START_FAILED/INTERRUPTED와 종료 코드입니다.
실행 전후 대상 파일 변경은 stable_during_run=false이며 통과 근거로 사용하지 않습니다.
check는 명령을 재실행하지 않고 계획·대상 해시를 비교해 CURRENT/STALE/INVALID를 반환합니다.
관련 요구는 참조일 뿐이며 requirements_verified=false, 테스트 수는 알 수 없습니다.
기존 spec_evidence 및 검토 보고서의 요구별 PASS로 자동 변환하지 않습니다.

POSIX에서 새 프로세스 그룹으로 실행하고 완료·시간 초과 시 그룹을 정리합니다.
명령 인자는 결과에 남으므로 비밀값을 전달하지 않습니다. stdout/stderr는 저장하지 않습니다.
현재 권한·환경을 상속하며 샌드박스가 아닙니다. 지정하지 않은 파일·환경 변화는 감지하지 않습니다.
계획 파일 4MiB, 대상 최대 200개·각 8MiB, 중복·빈 입력 거부. 출력은 새 파일만 허용합니다.

완료 조건: 실제 명령 성공/실패, 시간 초과, 실행 파일 누락, 파일 변경·삭제, 계획 변경,
잘못된 요구 ID·경로·중복, 셸 구문 미해석, 결과 덮어쓰기 거부를 자동 검사합니다.

## 변경 검토 보고서 연결

report에 반복 가능한 --command-evidence를 추가합니다. 기존 --evidence와 함께 또는 단독 사용합니다.
명령 근거만 있을 때 성공 상태는 COMMANDS_CURRENT_REVIEW_PENDING이며 요구별 PASS로 표시하지 않습니다.
같은 명세인지 확인하고 모든 명령의 유효한 성공, 요청 요구 ID 포함, 현재 연결 파일의 해시 범위 포함을 검사합니다.
오래됨·실패·실행 중 변경·범위 누락은 CHECKS_REQUIRED입니다. 다른 명세는 입력 오류로 거부합니다.
기존 요구 삭제·테스트 제거 검사와 사람 검토 대기는 유지합니다.
최초 보고서 연결 단계에서는 unittest 연결 명세를 사용했습니다. 아래 명령 계획 연결 확장에서 prepare 제약을 해소합니다.

## 명령 계획을 사용하는 명세 연결

traceability의 테스트 항목은 기존 {path, case} 또는 {path, command_plan} 중 하나입니다.
command_plan은 실행할 명령이 아니라 command_evidence의 계획 JSON 경로입니다.
같은 명세·요구 ID를 참조하고 테스트·해당 요구의 구현 파일을 해시 범위에 포함해야 합니다.
계획이 열거한 파일 전체를 baseline에 포함하여 작업 폴더 복사와 변경 감지에 사용합니다.
준비·영향 검사·보고서는 두 종류를 지원하며 명령을 자동 실행하지 않습니다.
기존 unittest 실행기는 명령 항목이 있으면 명확히 거부하며 자동 PASS로 건너뛰지 않습니다.
Node.js 테스트 실패→구현→명령 통과→검토 보고서를 실제 실행으로 확인합니다.
