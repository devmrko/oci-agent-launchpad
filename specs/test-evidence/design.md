# 요구별 테스트 실행 근거 설계

사용자는 구현 명세에 연결한 테스트가 실제로 통과했는지, 그 뒤 코드가 바뀌었는지 확인할 수 있어야 한다.

- 기존 traceability.json을 그대로 사용한다. 중복 연결된 테스트는 한 번 실행한다.
- 신뢰하는 저장소의 Python unittest만 명시적인 run 명령으로 실행한다. 셸 명령은 명세에서 받지 않는다.
- 각 테스트를 별도 프로세스에서 실행하고 제한 시간을 적용한다. 실패, 오류, skip, expected failure, 실행 0건은 통과가 아니다.
- 실행 전후 연결된 파일의 SHA-256을 비교한다. 실행 중 변경되면 근거를 무효로 표시한다.
- 결과는 요구 ID별 판정, 테스트별 집계, 파일 해시, Python 버전과 시각을 포함한 JSON으로 새로 저장한다. 기존 파일은 덮어쓰지 않는다.
- check는 실행 없이 파일 해시를 비교한다. 현재 파일과 일치해도 실패한 테스트가 통과로 바뀌지 않는다.
- 범위는 명세에 연결된 파일이다. 외부 의존성·환경·연결하지 않은 파일, 테스트의 의미적 충분성, 배포 성공은 보증하지 않는다. 서명된 감사 증적도 아니다.

검증: 통과/실패/skip/expected failure/timeout, 변경 후 stale, 실행 중 변경, 출력 덮어쓰기 방지와 실제 출장비 예제 실행.
