# 고객 업무 의도와 에이전트 설계 양식

고객·제품 책임자·개발자·운영자가 함께 작성하는 AI-DLC 적용 양식입니다. 제품 선정 전에 해결할 업무와 성공 기준을 합의하고 구현·배포·운영까지 추적합니다. `[필수]`는 착수 전 답변, `[조건부]`는 해당 기능 사용 시 답변, `[옵션]`은 생략 이유를 기록합니다. 미정은 추정값으로 채우지 않고 담당자·확정 시점을 적습니다.

방법 근거: [AI-DLC 방법론](https://prod.d13rzhkk8cj2z0.amplifyapp.com/aidlc.pdf)의 Intent·Unit·Bolt, Inception·Construction·Operations와 사람의 검토 원칙. 실행 단계 근거: [AWS AI-DLC workflows](https://github.com/awslabs/aidlc-workflows/tree/dc85f350886c5beec6e44d1460ddb41c9d133b60)의 requirements-analysis와 build-and-test. 아래 항목은 OCI 적용을 위해 작성한 양식이며 원문의 공식 템플릿을 그대로 복제한 것은 아닙니다.

## 1. Inception — 무엇을 왜 만드는가

| 항목 | 구분 | 작성할 값과 안내 |
| --- | --- | --- |
| 업무 의도 | 필수 | 누가 어떤 상황에서 무엇을 완료하려 하는가? |
| 현재 문제 | 필수 | 현재 절차, 병목, 관측한 근거. 추정은 따로 표시 |
| 사용자와 업무 책임자 | 필수 | 사용 역할, 최종 판단자, 요구 검토자 |
| 성공 기준 | 필수 | 업무 완료 정의, 기준선, 목표, 측정 방법·시점 |
| 대표 여정 | 필수 | 입력 → 조회/판단 → 사용자 확인 → 결과 |
| 제외 범위 | 필수 | 이번에 처리하지 않을 업무와 실패 시 안내 |
| 기존 시스템 | 필수 | 연결 API·DB·화면, 소유 팀, 변경 가능 범위 |
| 데이터 | 필수 | 출처, 접근 주체, 민감도, 사용 권한, 샘플 확보 여부 |
| 배포 책임 | 필수 | 리전·구획·대상 환경·예산 한도·종료 책임자 |
| 장기 기억 | 옵션 | 무엇을 왜 기억할지, 동의·조회·삭제·보관기간 |
| 코드/브라우저 실행 | 옵션 | 필요한 이유, 허용 네트워크, 격리와 종료 조건 |

### AI 질문과 사람의 답변

| 질문 ID | 미확정 내용·선택지·영향 | 사람 답변 | 답변자·날짜 | 반영 요구 ID |
| --- | --- | --- | --- | --- |
| Q1 | 예: 요청을 바로 등록할지, 확인 후 등록할지 | 미정 | 미정 | FR1 |

AI는 모순·누락·애매한 성공 기준을 먼저 질문합니다. 실제 고객 답변, 작성자의 가정, 합성 예시를 구분합니다. 검토자는 질문이 해결됐는지와 다음 단계 진행 여부를 기록합니다.

### 요구사항과 수용 기준

| ID | 구분 | 사용자 행동과 기대 결과 | 실패·경계 사례 | 검증 방법 | 출처 질문 |
| --- | --- | --- | --- | --- | --- |
| FR1 | 필수 | 구체적인 행동과 결과 | 권한 없음·중복·취소 | API/업무 시험 | Q1 |
| NFR1 | 필수 | 응답 시간·동시성·정확도 목표 | 측정 환경·허용 실패율 | 측정 절차와 표본 | Q2 |

수치가 미정이면 미정으로 남깁니다. 실제 측정 전에는 목표를 달성 결과로 적지 않습니다.

## 2. Construction — 어떻게 만들고 검증하는가

| 설계 항목 | 구분 | 작성할 값 |
| --- | --- | --- |
| 실행 구조 | 필수 | 요청 경로, 실행 프로세스, 상태 저장 위치, 장애 시 처리 |
| Identity·권한 | 필수 | 인증 방식, 역할별 동작, 사용자·조직 격리, 서비스 권한 |
| 도구·Policy | 도구 사용 시 필수 | 도구별 입력/출력, 읽기/쓰기, 허용 조건, 승인 주체, 재시도·중복 처리 |
| 모델 | 모델 사용 시 필수 | 공급자·모델·리전, 입력 데이터, 제한시간, 실패·잘못된 출력 처리 |
| 검색 | 검색 사용 시 필수 | 문서 출처·권한·갱신, 근거 없음 처리, 품질 평가 세트 |
| Memory | 기억 사용 시 필수 | 세션과 장기 기억의 경계, 키·보관·삭제, 동시 수정 처리 |
| 관측 | 필수 | 요청·실행·배포 ID 연결, 기록할 단계, 오류·지연·사용량, 마스킹 |
| 평가 | 필수 | 정상·실패·권한·악성 입력 사례, 기대 결과, 회귀 기준 |
| 재사용 | 필수 | Foundation·플랫폼 버전, 앱 고유 코드, 공통 기능 개선 위치 |

### Unit과 Bolt 실행 계획

| Unit | 책임 범위·입출력 | 의존 Unit | 담당자 | Bolt 목표·시간 범위 | 완료 증거 |
| --- | --- | --- | --- | --- | --- |
| U1 | 인증과 세션 등 | 없음 | 미정 | 동작 단위와 검증 | 테스트/리뷰 링크 |

각 Bolt 후 실제 변경·시험·미해결 문제와 다음 작업을 기록합니다. 코드를 생성했다는 사실과 요구를 만족했다는 증거를 구분합니다.

## 3. Operations — 어디에 배포하고 어떻게 운영하는가

| 항목 | 구분 | 작성할 값 |
| --- | --- | --- |
| 배포 산출물 | 필수 | 소스 커밋, 의존성 버전, 이미지 digest/패키지 hash |
| Companion 경로 | 필수 | 소스·빌드·프로젝트·환경, 제공 기능과 추가 구현 구분 |
| 비밀정보 | 조건부 | Vault 등 참조 위치·권한·회전 책임. 실제 값 기재 금지 |
| 시작·상태 확인 | 필수 | 실행 명령, 포트, 준비 상태, 외부 접근 범위 |
| 상태 보존 | 상태 저장 시 필수 | DB/볼륨, 백업·복구·스키마 변경 |
| 관측 연결 | 필수 | 백엔드·대시보드·알림, 버전과 요청의 연결 확인 |
| 장애·복구 | 필수 | 실패 감지, 재시도, 이전 버전 복구, 담당자 |
| 비용·종료 | 필수 | 예산, 사용량 확인, 데모 종료일, 삭제·보존 대상 |

### 검증과 인계

| 요구 ID | 대상 버전·환경 | 실행 명령/절차 | 실제 결과 | 증거 | 미해결 항목·담당자 |
| --- | --- | --- | --- | --- | --- |
| FR1 | 미정 | 미정 | 미실시 | 없음 | 미정 |

검토 결과: 진행/수정/보류, 검토자, 날짜, 근거를 기록합니다. 배포 성공과 업무 성공은 각각 확인합니다. 로컬 합격을 운영 합격으로 바꾸어 적지 않습니다.

## 채워진 예제와 확장 예시

[사내 안내·요청 접수 설계](../examples/service-desk/aidlc/design.md)가 첫 실행 예제입니다. 같은 양식을 아래 업무에도 적용할 수 있습니다. 아래 두 가지는 시나리오 제안이며 아직 구현하지 않았습니다.

| 업무 | 필수 흐름 | 옵션 | 중요한 수용 기준 |
| --- | --- | --- | --- |
| 사내 지원 | 규정 근거 → 요청 초안 → 승인 접수 | 선호 언어 기억 | 승인 전 미접수·사용자 격리 |
| 상품 상담 | 조건 입력 → 카탈로그 조회 → 추천 근거 | 장바구니·이미지 try-on | 없는 재고를 판매 가능하다고 안내하지 않음; 결제는 별도 승인 |
| 운영 장애 조사 | 경보 → 허용된 지표·로그 조회 → 원인 가설 | 승인 후 복구 실행 | 읽기 전용 기본; 근거와 가설 구분; 변경 전 승인 |
